# Nothing below is pinned upstream, and on Python 2 the resolver now
# backtracks the whole pytest stack down to pytest 3.5.1 -- which predates
# `Node.get_closest_marker`, so tests/conftest.py's
# pytest_collection_modifyitems raises AttributeError and the pypy2.7 legs
# collect zero tests. These are the newest releases that still support
# Python 2, i.e. what the resolver picked when 20.3.4 was cut.
#
# The Python 3 stack is bounded just above the 2021-01-23 releases the
# release-date index serves, because the GitHub legs add live PyPI as an extra
# index for cryptography (see above) and that also exposes a present-day
# pytest. pip 20.3.4's suite carries per-class state in nose-style
# `setup`/`teardown` methods (tests/lib/options_helpers.py's
# AddFakeCommandMixin, test_configuration.py's ConfigurationMixin, and the same
# pattern in test_utils / test_req / test_utils_unpacking); pytest 8 removed
# support for those, so the methods never run and ~150 unit tests fail on state
# that was never set up (`unknown command "fake"`, `object has no attribute
# 'configuration'`). Bounding the whole stack rather than pytest alone keeps
# the resolver from deep-backtracking the plugins that require pytest >= 7.
#
# The bound is what keeps the py3.5 leg resolvable, so these stay ranges rather
# than exact pins: pytest 6.2.x (and its era's plugin releases) dropped Python
# 3.5, so `pytest==6.2.1` makes windows-latest/3.5 fail outright with "Could
# not find a version that satisfies the requirement pytest==6.2.1". Under an
# upper bound each interpreter resolves the newest release of the era it still
# supports -- 3.5 lands on pytest 6.1.2, 3.6+ on 6.2.x -- and no leg can reach
# the present-day pytest on the extra index.
pytest<6.3; python_version >= '3'
